# Case Management + Search API — Reference

Owner: Yojit Wagh
Module path in repo: `backend/app/case_management/`

## Base URL

Local development (default uvicorn port for this module — the timeline
module already uses Flask on :5000, so this app runs on :8000 to avoid
a clash when both are up at once):

```
http://127.0.0.1:8000
```

All case-management routes are versioned and prefixed:

```
http://127.0.0.1:8000/api/v1
```

## Endpoints

| Method | Path                              | Purpose                                   |
|--------|------------------------------------|--------------------------------------------|
| POST   | `/api/v1/cases`                    | Create a case                              |
| GET    | `/api/v1/cases`                    | List cases (paginated)                     |
| GET    | `/api/v1/cases/{case_id}`          | Get one case + its evidence                |
| PUT    | `/api/v1/cases/{case_id}`          | Update a case (partial)                    |
| DELETE | `/api/v1/cases/{case_id}`          | Delete a case and its evidence             |
| POST   | `/api/v1/cases/{case_id}/evidence` | Attach evidence to a case                  |
| GET    | `/api/v1/evidence/{evidence_id}`   | Get a single evidence item                 |
| GET    | `/api/v1/search/cases`             | Search/filter cases                        |
| GET    | `/api/v1/search/evidence`          | Search/filter evidence                     |
| GET    | `/api/v1/health`                   | Health check                               |

### Search query params

`/api/v1/search/cases`:
- `q` — free-text match across title, description, case_number, location
- `status` — open | under_investigation | closed | archived
- `crime_type` — partial match, e.g. `robbery`
- `priority` — low | medium | high | critical
- `assigned_investigator` — partial match
- `tag` — exact tag match
- `page`, `page_size` — pagination

`/api/v1/search/evidence`:
- `q` — free-text match across description, source
- `evidence_type` — image | video | document | witness_statement | cctv_frame | physical | other
- `case_id` — restrict to one case
- `page`, `page_size`

## Sample case JSON

See `sample_case.json` — this is the exact shape `GET /api/v1/cases/{id}`
returns, and roughly what other modules (timeline, NLP, image analysis,
dashboard) should expect to read/write against. Fields that other
modules will attach detections/entities to live under each evidence
item's `extra_metadata` (kept as free-form JSON on purpose so new
modules don't force a migration on this schema every time).

## Running it locally

```bash
cd backend
python -m venv venv
source venv/bin/activate      # venv\Scripts\activate on Windows
pip install -r requirements.txt

# point at your local Postgres, or leave default for docker-compose
export DATABASE_URL="postgresql://csia_user:csia_password@localhost:5432/csia_db"

uvicorn app.main:app --reload --port 8000
```

Interactive API docs (auto-generated by FastAPI) once running:

```
http://127.0.0.1:8000/docs
```

## Notes for the team

- Every field other modules need should go through `extra_metadata`
  on `Evidence` first if it's exploratory — promote it to a real column
  only once it's stable, and flag it here so the schema stays a single
  source of truth.
- `Case.status`, `Case.priority`, `Evidence.evidence_type` are enums —
  adding a new value means updating `models.py` and telling the team,
  since the dashboard/search will filter on these.
